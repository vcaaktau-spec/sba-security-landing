# SBA Security — новый концепт сайта (2026)

Рабочий документ по мотивам брейншторма с Павлом. Цель — зафиксировать концепцию перед тем, как переделывать сайт, чтобы не тратить силы на неправильную ветку.

## 1. Идея одним абзацем

Человек заходит на сайт с одной мыслью — "нужно видеонаблюдение" (или СКУД/сигнализация/сеть). На сайте он: понимает, зачем это нужно и чем рискует, если не поставит или сэкономит; за пару минут подбирает оборудование — сам или с помощью AI-подсказчика; получает предварительный расчёт с работой; оставляет заявку и получает КП/смету. Купить оборудование отдельно нельзя — только с монтажом.

## 2. Главная страница — полная переделка

Это самая важная часть сайта, делаем по максимуму информативно и современно (2026), в минималистичном стиле в духе Linear, но премиально — не голый минимализм, а выверенный, дорогой на вид.

Порядок блоков:

1. **Hero** — сразу понятно, кто мы и что делаем (остаётся тактическая айдентика: Sentinel/Tactical/Prestige, blueprint-эстетика — она уже есть и хорошо ложится в Linear-стиль).
2. **Боли** — блок про цену бездействия: реальные мировые примеры, что бывает, когда видеонаблюдение не ставят или экономят на нём (кражи, страховые отказы, потери на производстве и т.д.). Через факты и кейсы, не через страх ради страха.
3. **Наши плюсы** — почему SBA, а не самостоятельная установка/случайный монтажник.
4. **Два входа в расчёт** (см. раздел 3) — главный CTA блок, разводит пользователя на "с оборудованием" и "просто посчитать монтаж".
5. Дальше — существующие блоки (кейсы/проекты, отзывы, статистика) остаются, но визуально приводятся к общему стилю.

Аудитория двойная: обычный человек/бизнес-собственник **и** снабженец/процурмент крупной компании — второй сегмент триггерится строгой подачей фактов, наличием КП в понятном формате, скоростью получения официального документа.

## 3. Два пути расчёта

### 3.1 Новый интерактивный подбор оборудования (главный путь)

Стартовый экран предлагает выбор:

- **С помощью AI** — пользователю задаются наводящие вопросы (сколько камер, где ставить — улица/помещение/периметр, что важно — ночная съёмка, распознавание лиц, дальность и т.д.). Ответы уходят в Gemini API вместе с данными нашего каталога, Gemini возвращает конкретные позиции из каталога как рекомендацию (несколько вариантов на выбор, не одну).
- **Вручную** — открывается каталог, пользователь сам выбирает нужные позиции.

Оба пути ведут в одну точку — **корзину**. В корзине нельзя оформить покупку, только:

- пересчитать в смету/КП вместе со стоимостью работ (переиспользуем логику монтажа/кабеля/HDD и т.п. из текущего калькулятора, но привязываем её к реальным выбранным товарам, а не к абстрактным "камера 2MP"),
- обязательная плашка: "цены ориентировочные, точная стоимость — после выезда специалиста",
- получить готовый файл (КП / смета / invoice — по сути один и тот же документ) — на скачивание и/или на WhatsApp/email, как сейчас с текущим калькулятором.

### 3.2 Старый калькулятор — остаётся, но как отдельная опция

Текущий квиз-калькулятор (Calculator.tsx) **не трогаем** содержательно. Он остаётся как отдельный, второстепенный инструмент — "быстро посчитать только работу", без привязки к конкретным товарам из каталога. Ссылка на него — где-то рядом с главным CTA, но не как основной путь.

## 4. Что нужно построить технически

- **Каталог оборудования** — таблица товаров в БД (категория, фото, название, характеристики, базовая цена "как есть"). Это новая сущность, её ещё нет — сейчас в схеме есть только `projects` (объекты клиентов) и (недавно добавленный, пока неактивный) кэш цен под старый калькулятор.
- **Корзина** — состояние на клиенте (или в БД, если нужно сохранять между визитами), список выбранных товаров + количество.
- **Расчёт сметы по корзине** — логика "оборудование + монтаж" по товарам из корзины (не по абстрактным тирам, как в старом калькуляторе).
- **Gemini-интеграция** — серверный эндпоинт, который принимает ответы на наводящие вопросы + список товаров каталога, обращается к Gemini API, возвращает 2-3 рекомендованных набора. Нужен `GEMINI_API_KEY` — добавляется в переменные окружения Vercel (не пишем ключ в код и не присылаем его в чат).
- **Генерация КП/сметы** — переиспользуем PDF-механизм, который уже сделан для старого калькулятора (jsPDF + html2canvas), но с новым макетом под корзину товаров.
- **Визуальный стиль** — Linear-минимализм + премиальность: много воздуха, чёткая типографика, сдержанная анимация, тактическая айдентика (моноширинные лейблы, blueprint-сетка) остаётся, но становится более выверенной и "дорогой".

## 5. Наполнение каталога товарами

Отдельный вопрос — откуда берутся товары и фото/характеристики для каталога (barlau.kz публично отдаёт цены, но не отдаёт машиночитаемый экспорт — нужен либо парсинг карточек по одной, либо прайс-лист/фиды от поставщика, либо ручное наполнение силами Павла). Это не блокирует дизайн и структуру — можно спроектировать всё на 10-15 тестовых товарах и наполнять каталог параллельно.

## 6. Порядок работ (предлагаемый)

1. Каталог: модель данных + страница/раздел с товарами (без AI, без корзины) — фундамент, без него ничего не работает.
2. Корзина + пересчёт сметы по товарам из корзины + скачивание КП.
3. Наводящие вопросы + Gemini-рекомендации поверх готового каталога/корзины.
4. Редизайн главной страницы (Hero, боли, плюсы, два входа в расчёт) под новую логику и Linear-стиль.
5. Причёсывание визуального стиля по всему сайту.

Старый калькулятор весь процесс не трогает и продолжает работать как есть.
